    02 / GET YOUR HANDS ON IT

    Small commands. Big possibilities.

    Open the Vers docs ↗ (opens in a new tab)

    Run these in your own terminal with the Vers CLI installed and authenticated. Set VM_ID to a machine ID from your stack. The buttons below only copy commands.

    01ORIENT

    Meet your machines.

    Find your frontend and database. On the Vers canvas, every VM is a live piece of your system.

    vers list --json
    02INSPECT

    Take a look inside.

    Run a command on a machine. It’s a real computer, with its own processes, files, and operating system.

    vers exec "$VM_ID" -- uname -a
    03BRANCH

    Try another direction.

    Fork a machine into two branches. Explore a change in each, with your starting machine still in place.

    vers fork "$VM_ID" --count 2
    04CHECKPOINT

    Keep a starting point.

    Save a machine’s state before an experiment. Use the current Vers CLI for checkpoint and restore commands.

    vers checkpoint "$VM_ID" --name before-change
    ⑂

    A branch of the frontend still talks to the same database.

    Want an isolated experiment? Branch the database too, then update the new frontend’s database connection. Branching one machine doesn’t automatically branch the whole stack.
